# Руководство по защите проекта ForgeService

## Общая концепция рассказа (2–3 минуты на концепцию + демо)

**Ключевой посыл:**
> «ForgeService — это не просто приложение. Это полноценная профессиональная информационная система для управления небольшим автосервисом, которая решает реальные боли бизнеса.»

## Структура защиты (рекомендуемая)

### 1. Введение (30–40 сек)
- Проблема малого и среднего автосервиса:
  - Всё в Excel, блокнотах, WhatsApp, на бумаге.
  - Нет единой картины по автомобилю (история ремонтов теряется).
  - Склад "на глаз".
  - Невозможно нормально контролировать загрузку боксов и мастеров.
  - Фотофиксация работ либо отсутствует, либо лежит в разрозненных папках.

- Решение: единая система (сервер + мобильные клиенты), которая работает полностью локально.

### 2. Архитектура (1 мин)
- Локальный сервер на Python (FastAPI) — стоит на компьютере в офисе.
- Мобильное приложение на Android (Jetpack Compose) для приёмщиков и мастеров.
- WebSocket — реал-тайм синхронизация между всеми устройствами.
- Room — полноценная работа в оффлайн (мастер на выезде).
- Богатая доменная модель (12 сущностей).

Подчеркнуть: **всё хранится локально**, данные не уходят в облако — важно для многих СТО.

### 3. Демонстрация (самое важное — 4–6 минут)

**Обязательно покажи следующее:**

1. **Запуск сервера** + Swagger (`/docs`)
2. **Сидер** — сразу много реалистичных данных
3. **Два клиента одновременно** (два телефона или эмулятор + телефон):
   - Создаёшь заказ-наряд на одном устройстве.
   - На втором устройстве он появляется в реальном времени.
4. **Переход по статусам** + broadcast обновлений.
5. **Добавление фото** в заказ-наряд + **аннотирование** (нарисуй стрелку "тут трещина рычага").
6. **Списание запчасти** со склада и автоматический пересчёт стоимости.
7. **Карточка автомобиля + история** (таймлайн) — покажи, что по одному VIN можно посмотреть все предыдущие ремонты.
8. **Дашборд** руководителя (цифры, предупреждения по складу).
9. **Генерация PDF** (если успеем сделать).

### 4. Технические фишки, которые стоит упомянуть

- Полноценный жизненный цикл Заказ-наряда со статус-машиной.
- Реал-тайм через WebSocket (подписка на конкретный ЗН и глобальный канал).
- Оффлайн-first архитектура.
- Нормальная работа с файлами (фото хранятся на сервере, отдаются статически).
- Богатые связи в БД (много join'ов в детальном просмотре ЗН).
- Фото-аннотации хранятся в отдельной таблице (можно масштабировать).

### 5. Что можно развивать дальше (показывает глубину)

- Полноценный PDF-генератор актов и счетов (reportlab).
- Интеграция с 1С (экспорт).
- Мобильное приложение для клиента (просмотр статуса своего авто по номеру).
- Аналитика + ML (какие работы чаще всего идут вместе).
- Учёт времени мастеров по часам.
- Печать на термопринтере (акты приёмки).

### Полезные фразы

- «Это не учебный проект. Это система, которой реально можно пользоваться в небольшом СТО на 4–6 боксов.»
- «Сервер поднимается одной командой на обычном офисном компьютере. Никаких облаков и подписок.»
- «Мастер может работать даже без интернета — данные синхронизируются, когда он возвращается в зону покрытия Wi-Fi.»
- «Фотофиксация с аннотациями даёт юридическую защиту сервису и прозрачность для клиента.»
